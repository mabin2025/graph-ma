# 服务与 Agent 专项检查

仅在分析在线服务、Agent 或 RAG 时读取。以下是源码勘察项，按项目实际能力选择；不是要求把全部信息塞进图，也不是要求新增这些能力。

## 请求与数据链路

追踪 API 或消息入口、配置加载、客户端选择、上下文构造、路由条件与优先级、模型或工具调用、输出组装和回写。记录关键外部依赖与状态的生命周期，核实流式和非流式是否采用不同链路。

## RAG 检索与知识入库

核实文档来源、切分与索引写入、检索触发、查询构造、过滤和租户隔离、TopK、阈值、重排、引用与上下文组装。检索参数不等于召回质量；效果结论需要对应评估或运行证据。区分知识库、会话记录和用户长期记忆。

## 长短期记忆专项检查

分析记忆模块时，不能只画“短期记忆 → 长期记忆”。至少核实：

- 短期记忆的载体、生命周期、轮数或 token 截断规则。
- 长期记忆的写入触发、抽取或摘要方式。
- 存储介质、索引键、用户/会话/租户隔离方式。
- 召回触发、查询构造、TopK、阈值、过滤和排序。
- 新消息、历史对话、用户画像、知识片段的上下文拼装顺序。
- 去重、覆盖、更新、过期、删除和冲突处理。
- 失败时是否降级为仅短期记忆或无记忆。
- 敏感信息、越权召回和跨会话污染风险。
- 代码中是否真的存在长期记忆；不要把对话历史误写成长记忆。

优先把记忆图组织为：

`写入链路 + 存储边界 + 召回链路 + 上下文组装 + 生命周期/风险`

## 路由与规划专项检查

至少核实：

- 路由发生在模型前还是模型后。
- 条件来自规则、模型输出、状态字段还是异常类型。
- 路由优先级、默认分支和终止条件。
- 是否存在循环、最大步数、超时和重复工具调用保护。
- 规划结果如何转换成可执行任务。
- 分支结果如何合并并进入最终输出。

## 工具执行专项检查

至少核实：

- 工具注册和可见性控制。
- 工具选择、参数生成和参数校验。
- 权限、超时、重试、幂等和异常映射。
- 返回值标准化、截断和注入上下文的方式。
- 外部副作用及其授权边界。

## 输出与回写专项检查

至少核实：

- 最终答案由谁组装。
- 中间状态如何裁剪或归档。
- 会话、记忆、缓存、数据库或事件如何回写。
- 流式与非流式输出是否走不同链路。
- 失败时是否返回部分结果、兜底答案或错误码。


## 结果证据与风险

按需复用真实调用轨迹、检索评估或监控图；延迟要说明统计窗口与分位数，成功率要说明分母。没有运行证据时仅描述源码机制。降级、超时、重试、幂等和人工介入只描述实际存在的逻辑；复杂路径独立解释，主图仅保留会改变主要结果的分支。
